# 扩充规则库后的错误级测评实验报告

本文档整理 PhysicsVerifier 在 **3000 样本规模扩充规则库**（`catalogs/rules_unified_3000.json`）接入后，100 条错误级召回集上的端到端测评结果，并与扩充前/优化前的基线对比。测评均关闭符号核查（`--no-symbolic-check`），检查模型分别为 **qwen3-30b-a3b-instruct-2507** 与 **qwen3-235b-a22b-instruct-2507**。

---

## 1. 规则库与实验背景

### 1.1 扩充规则库概况

| 项目 | 旧版参考库 | 扩充版（当前主库） |
|------|------------|-------------------|
| 文件 | `catalogs/unified_rule_library_v2_distilled300_20260503.json` | `catalogs/rules_unified_3000.json` |
| 构建来源 | 约 300 条蒸馏经验 | 约 3000 条样本抽取 + 旧版高价值规则 seed |
| 可执行规则数 | ~300 级 | **约 4875 条** |
| 覆盖 topic 数 | 较少 | **93** 个 topic 含规则 |
| Scenario cluster | 无/少 | **约 488** 个 |
| 运行时 schema | 含 `match_features`、`retrieval_hints` | 最小化 schema（`title/trigger/check_logic` 为主） |

组织结构统一为：**Domain → Topic → Scenario Cluster → Rule Group → Rule**。详见 `规则库构建阶段说明.md`。

### 1.2 测评集与协议

- **数据集**：`data/derived/combined_language_dual_chain_seed20260508_test200/annotated_chain/error_eval_dataset_100.json`
- **规模**：100 道样本，**688** 个可定位 GT 错误（location match）
- **符号核查**：全部关闭，仅评测「规则检索 + LLM 语义检查」
- **评测脚本**：`scripts/run_error_level_3000_30b_235b_no_sym.sh`

## 2. 运行时优化（与规则库扩充配套）

仅替换 JSON 文件不足以直接提升指标。接入 `rules_unified_3000.json` 后，仓库还做了以下 **运行时修复与 235B 专用调优**（当前 `main` 代码已包含）：

| 优化项 | 位置 | 作用 |
|--------|------|------|
| 规则 `match_features` 运行时合成 | `core/rule_catalog_retrieval.py` → `ensure_rule_match_features()` | 最小 schema 规则可被检索打分，否则得分恒为 0、不进入 LLM |
| Topic 检索关键词运行时合成 | `enrich_minimal_topic_candidate()` | 避免 90% 样本 topic 得分为 0 后按字母序误选「AC Circuits」 |
| 235B recall prompt | `core/semantic_rule_checker.py` → `_llm_prompt_profile()` | 降低「不确定即返回空」的保守行为 |
| 235B `precision_mode=balanced` | `core/physics_rule_verifier.py` | 保留 `warning` 级诊断（strict 模式会丢弃） |
| LLM 输出解析 | `_coerce_llm_diagnostics()` | 统一解析 `{"violations": [...]}` 等格式 |

30B 默认仍使用 **conservative prompt + strict release gate**；235B 自动启用 **recall prompt + balanced gate**。

## 4. 指标对比（location match）

| 批次 | Recall | Precision | F1 | 样本触发率 | 定位命中率 | 匹配 GT 数 |
|------|--------|-----------|-----|------------|------------|------------|
| 30B 旧 | 20.6% | 52.4% | 29.6% | 100% | 85% | 142 / 688 |
| **30B 优化** | **23.4%** | 51.6% | **32.2%** | 99% | 85% | **161 / 688** |
| 235B 旧 | 2.3% | 48.5% | 4.4% | 23% | 13% | 16 / 688 |
| **235B 优化** | **28.5%** | 46.8% | **35.4%** | 78% | 69% | **196 / 688** |

### 4.1 简要解读

**30B**

- Topic 检索优化带来 recall **+2.8 个百分点**（142→161 个匹配），触发率与 precision 基本稳定。
- 30B 对 conservative prompt 本就不敏感，主要收益来自 **检索链路修通**。

**235B**

- Recall 从 **2.3% → 28.5%**（约 **12 倍**），为三者中最高；F1 **35.4%** 亦高于 30B 优化版。
- 提升来自 **检索修复 + recall prompt + balanced gate** 的组合；旧版下 235B 大量规则检查返回 `[]`，且 warning 被 strict 模式过滤。
- Precision 略低于 30B（46.8% vs 51.6%），符合 recall 取向的权衡。

**横向**

- 在相同 3000 规则库与优化后检索下，**235B 优化版 recall 高于 30B 优化版**（28.5% vs 23.4%），但触发率更低（78% vs 99%）。

---

## 5. 为何 235B 在扩充与优化后提升最明显

1. **旧版几乎「不检查」**：规则得分为 0 → 不调用 LLM；topic 误选 → 规则与题目无关；235B 又严格遵循「无把握则 `[]`」→ 三重抑制。
2. **扩充库 + 合成特征 → 有规则可查**：约 4875 条规则中，与题目相关的经验可进入 top-6 语义检查。
3. **Topic 不再塌缩到 AC Circuits**：关键词合成后，100/100 样本 topic 得分 > 0，主 topic 与题意更一致（热力学、相对论、光学等）。
4. **235B 专用 prompt / gate**：在仍保持相对谨慎的前提下，愿意输出 `error`/`warning` 且 warning 不被丢弃。

30B 旧版已能「广撒网」式触发（100% 样本），故优化后边际提升较小；235B 从「几乎不报」到「适度报且 recall 最高」，边际最大。

## 6. 案例分析

以下三例均来自 **235B 旧版 → 235B 优化版**（`20260531_170624` → `20260601_101951`），展示「先前检不出 / 检不准 → 优化后可检出 GT 错误」的典型机制。GT 描述来自标注字段，预测来自 `error_verifier_results.json`。

---

### 案例一：摩卡壶热力学（理想气体与湿空气）— `cl_236_160651`

**题目概要**：意大利摩卡壶煮咖啡过程中，封闭气室、饱和蒸汽压与空气分压等热力学推导。

| 维度 | 235B 旧 | 235B 优化 |
|------|---------|-----------|
| 主 topic | AC Circuits（误选） | **Ideal Gas Law and Real Gas Behavior** |
| 诊断条数 | 0 | 10 |
| 匹配 GT | **0 / 10** | **6 / 10** |

**旧版为何未检出**

- Topic 检索失效时固定落到无关的 AC 电路 topic，所选规则与咖啡、湿空气、分压无关。
- 235B 对无关规则几乎一律返回 `violations: []`。

**优化后如何检出**

- 检索命中热力学 topic 及理想气体/湿空气相关规则（如 `norm_487fe3f6283c97d4`）。
- 模型引用学生式子并指出矛盾，例如：

  > *The partial pressure of air is incorrectly calculated by subtracting saturated vapor pressure from total pressure without verifying consistency with ideal gas law for a closed system.*

  引用：`p_{\text{air},2} = p_{\text{total},2} - p_{sv,2} = 96.4 \, \mathrm{kPa} - 34.0 \, \mathrm{kPa} = 62.4 \, \mathrm{kPa}`

**与 GT 对齐**

- 与 GT 错误 `cl_236_160651_e1`（气室体积假设不一致、湿空气处理错误）在 **paragraph 级** 匹配成功。

**启示**：扩充规则库使热力学经验规则 **可查**；topic 合成使 **查对题**；235B prompt 使 **敢报**。三者缺一，此题仍为零输出。

---

### 案例二：μ子束与狭义相对论观测 — `cl_132_54047`

**题目概要**：Alice 在高度 \(h\) 处以角度发射 μ 子，Bob 在地面远距离观测；涉及时延、Terrell 效应与参考系时间。

| 维度 | 235B 旧 | 235B 优化 |
|------|---------|-----------|
| 主 topic | AC Circuits（误选） | **Special Relativity (Time Dilation, Length Contraction)** |
| 诊断条数 | 0 | 5 |
| 匹配 GT | **0 / 6** | **4 / 6** |

**旧版为何未检出**

- 与案例一相同：错误 topic + 235B 保守空返回。

**优化后如何检出**

- 规则检查针对「坐标时与观测时混淆」「未建立光传播时延」等 SRD 触发。
- 示例诊断：

  > *Fails to distinguish observed time from coordinate time; uses coordinate time in Bob's frame without accounting for light propagation delay.*

  引用：\(t_B = h/(c\cos\theta)\) 一类竖直分量公式。

**与 GT 对齐**

- 匹配 `cl_132_54047_e1`：GT 指出学生仅用时间膨胀关系、未正确处理 μ 子运动与击中地面事件的观测几何。

**启示**：相对论 topic 在扩充库中有专门规则簇；**topic 修复**使 235B 首次对该题调用相关 SRD；recall prompt 使其输出带引用的 error 而非沉默。

---

### 案例三：全反射与倏逝波 — `cl_188_110801`

**题目概要**：几何光学全反射、倏逝波衰减常数 \(\alpha\)、\(k_{2z}=i\alpha\) 等推导。

| 维度 | 235B 旧 | 235B 优化 |
|------|---------|-----------|
| 主 topic | Total Internal Reflection（正确） | Total Internal Reflection |
| 诊断条数 | 1 | 6 |
| 匹配 GT | **0 / 6** | **3 / 6** |

**旧版为何未匹配 GT**

- 该样本 topic 在旧版中偶发正确（得分 > 0），曾有 1 条诊断，但与 GT 错误 span **未对齐**（location/paragraph 未命中）。
- 保守 prompt 下输出条数少，覆盖不足。

**优化后如何检出**

- 同一 topic 下选出更多光学经验规则，指出未由 \(\nabla\times\mathbf{E}\) 导出磁场、相位关系缺失等：

  > *The student sets \(k_{2z} = i \alpha\) but fails to show how this affects the magnetic field through Faraday's law...*

**与 GT 对齐**

- 匹配 `cl_188_110801_e1`：GT 认为衰减常数 \(\alpha\) 使用真空波长、介质波矢不一致。

**启示**：此例说明优化 **不只靠 topic 纠错**；在 topic 已正确时，**扩充规则 + recall 取向** 仍能提高 **检出条数与 GT 对齐率**（0→3 匹配）。

---

## 7. 结论与后续建议

1. **扩充规则库** 将可执行经验从数百条提升到约 **4875** 条，为错误级测评提供了覆盖基础。
2. **运行时合成 `match_features` / topic 关键词** 是接入最小 schema 库的必要条件，否则会出现「假跑通、零 recall」。
3. **235B** 需与模型行为匹配的 **prompt + release gate**；在优化配置下，235B recall **28.5%** 为当前最高，但仍低于理想巡检需求，precision 亦有提升空间。
4. **30B 优化版** recall **23.4%**，触发率极高（99%），适合作为高召回参考，但误报仍多。

**建议后续工作**

- 在规则库构建阶段预写入 `match_features` / `retrieval_hints`，减少对运行时合成的依赖。
- 按模型分 profile 固化 prompt 与 gate，并做 precision–recall 扫参。
- 对 topic 得分仍为 0 或泛化规则占比高的 topic 做规则质量与聚类细化（见 `规则库构建阶段说明.md`）。
