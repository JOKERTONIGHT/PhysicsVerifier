## 二、为何「定位漏检、语义检出」

Strict 要求 pred 的 quote 反查 span 后与 GT span **IoU≥0.5 或 coverage≥0.6**（或同段官方回退）；semantic 仅要求 `error_text` 与 `message+quote` **token 重叠≥3**，不看位置。

| 漏检类型 | 含义 | 在本集占比（30B） |
|----------|------|-------------------|
| Quote 无法定位 | quote 与原文格式/LaTeX 不一致，无法反查字符 span | 最常见 |
| 段落错位 | 诊断正确，quote 落在相邻/其他段落 | 较常见 |
| Span 不重叠 | 同一根因，quote 锚在下游公式/结论，GT 标在上游假设 | 较常见 |
| 综合诊断 vs 细 GT | 一条诊断覆盖多个子错，item-level span 对不齐多条 GT | Gemini 更典型 |

Paragraph 指标仅 12.4%，说明问题主要是 **落错段或无法定位**，而非「同段内偏几个字符」。

## 三、典型案例

### 案例 1 · Quote 无法定位（`cl_196_119724_e1`）

- **GT**：用 100°C 汽化潜热除以 180°C 沸点算熵变 — 物理不成立
- **Checker**：同样指出「不能把 100°C 潜热直接用于 180°C」
- **语义为何命中**：message 与 error_text 关键词高度重叠（潜热、100°C、180°C、熵等 token≥3）
- **定位为何漏检**：pred quote 与答案原文 LaTeX/标点不一致 → `_locate_quote_span` 失败 → 无 pred span → strict 无法计分

### 案例 2 · 段落错位（`cl_132_54047_e2`）

- **GT**：误用 `t_B = γ t_A` 处理有空间分离的事件（标注在第 **5** 段）
- **Checker**：同样批评时间膨胀误用，quote 选在第 **8** 段同类表述处
- **语义为何命中**：均围绕 Lorentz 时间膨胀误用，token 重叠 17
- **定位为何漏检**：pred 与 GT **paragraph_index 不同**，span 无交集 → IoU=0

### 案例 3 · Quote 锚在下游（`cl_83_4027_e2`）

- **GT**：将两球系统当成 charge `2q` 单粒子，忽略仅 A 球在电场中（第 **8** 段假设）
- **Checker**：同样指出「不能当成 2q 单粒子」，quote 落在第 **14** 段最终速度公式
- **语义为何命中**：「2q」「单粒子」「电场」等 token 重叠
- **定位为何漏检**：诊断指向同一根因，但 quote 锚在 **错误传播后的结论** 而非 GT 标注的 **源头步骤** → span IoU=0

### 案例 4 · 综合诊断 vs 细粒度 GT（`cl_116_37467`，Gemini）

- **GT e1/e2/e5**：分别标注动量定义、水平分量、最终加速度等多条独立 span
- **Checker**：一条诊断概括「变质量系统 F=b·u, F=Ma」，quote 在 `F = b·u`
- **语义为何命中**：与多条 GT 的 error_text 均有足够 token 重叠
- **定位为何漏检**：**一条 pred 只能匹配一条 GT**；quote span 与 e1 的 `ṁ·u`、e2 的「水平动量为零」等 **各自 span 均不重叠** → 多条 item-level FN，group 层则可能整组命中

## 四、符号层结论与计划

**结论**

- 不与语义竞争「概念/建模对不对」；语义稳定的部分符号层重复判断价值低
- 优先：**公式代数错误**（因子/幂次/导数）、**轨道/引力标度**、**量纲/符号/不等式约束**（如 v>c、 dE/dt 符号）
- 不宜符号化：跨题误触发、多步建模链、题意/叙事类、缺失型规则、标注噪声
- 规则 FP 主因 `rule_too_broad`（32）— 符号 pass 若基于宽泛 token，可能 **放大误抑制**，首轮禁止进 suppression

**计划**

- [ ] 小样本实验：对 formula_algebra / orbital_gravity 候选（见 `candidate_errors.json`）接入 equation_equivalence、dimension_check、sign_check 等 primitive
- [ ] 符号输出仅作 **structured evidence**，与语义 findings 并列，不参与 release gate
- [ ] 评估符号层单独报 precision/recall，与 semantic strict 解耦，避免重复计分
- [ ] 待 1500 规则库 symbolic manifest 就绪后，再与 TargetedRules / Validator 链路联调
