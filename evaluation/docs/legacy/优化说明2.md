## 一、目标与口径

### 1) 规则扩充源

- 以 `data/combined_language_only.json` 为大规模错题源。
- 重建一套 **1000 条错题扩充样本**（统一转换到 `evaluation_sample_300.json` 同类结构：`id/question/prediction/answer`）。

### 2) 测评集与评测策略

- 测试数据来自 `data/physics_rubric_data_1000.json`。
- 先采用小规模验证：**100条子集**（避免直接全量测评开销）。
- 指标采用严格口径：
	- precision / recall / F1 / accuracy
	- 符号检查无结论比例（inconclusive ratio）
	- 全样本无结论比例（sample_all_inconclusive_ratio）
	- 缺失代码绑定抑制比例（missing_binding_ratio）

### 3) 规模曲线实验

- 从 1000 条扩充源中按每 200 条做检查点：
	- 200, 400, 600, 800, 1000
- 每个检查点重复完整流水线，最后聚合成曲线数据（CSV/JSON）。

## 二、测评指标定义与计算方式（严格口径）

本节对应 `scripts/compute_strict_eval_metrics.py` 与 `scripts/prepare_rubric_eval_subset.py` 的当前实现，所有指标均按同一口径计算。

### 1) 样本层标签定义

- 评测样本来自 `rubric_eval_100_meta.json` 的 `samples`。
- 仅 `is_evaluable=True` 且 `gt_is_incorrect` 为布尔值的样本进入分类指标统计（记为 `total_evaluable_samples`）。
- 严格 GT 定义：
	- 先对 `ground_truth_label` 与模型答案做归一化（去空白、去 `\left/\right`、统一小写等）。
	- 若 `ground_truth_normalized == prediction_normalized`，则 `strict_exact_match=True`，`gt_is_incorrect=False`。
	- 否则 `strict_exact_match=False`，`gt_is_incorrect=True`。
- 预测正类定义（pred positive）：`run_verifier.py` 主输出中该样本 `diagnostics` 非空，即 `pred_has_diagnostic=True`。

### 2) 混淆矩阵定义

对每个可评测样本，按 `(pred_has_diagnostic, gt_is_incorrect)` 计数：

- TP：预测有诊断，且 GT 为错误。
- FP：预测有诊断，但 GT 为正确。
- FN：预测无诊断，但 GT 为错误。
- TN：预测无诊断，且 GT 为正确。

记：

$$
N = TP + FP + FN + TN
$$

### 3) 分类指标计算

- Precision：

$$
	ext{Precision} = \frac{TP}{TP + FP}
$$

- Recall：

$$
	ext{Recall} = \frac{TP}{TP + FN}
$$

- F1：

$$
F1 = \frac{2 \cdot \text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}
$$

- Accuracy：

$$
	ext{Accuracy} = \frac{TP + TN}{N}
$$

分母为 0 的边界处理与代码一致：对应指标置为 `0.0`。

### 4) experience code 检查统计指标

统计来源为 symbolic audit 中每个样本的 `experience_code_checks` 与 `suppressed_diagnostics`。

- `experience_code_total`：所有样本中，结果属于 `pass/fail/inconclusive` 的检查条目总数。
- `experience_code_pass` / `experience_code_fail` / `experience_code_inconclusive`：按结果计数。
- `experience_code_inconclusive_ratio`：

$$
\frac{\text{experience\_code\_inconclusive}}{\text{experience\_code\_total}}
$$

- `samples_with_any_experience_check`：至少包含一条检查记录的样本数。
- `sample_all_inconclusive_ratio`：在有检查记录的样本中，“该样本所有有效检查均为 inconclusive 且无 fail”的比例。

$$
\frac{\text{sample\_all\_inconclusive}}{\text{samples\_with\_any\_experience\_check}}
$$

- `suppressed_total`：被抑制诊断总数（`suppressed_diagnostics` 总条目数）。
- `suppressed_missing_binding`：抑制原因 `reason == missing_experience_code_binding` 的条目数。
- `suppressed_missing_binding_ratio`：

$$
\frac{\text{suppressed\_missing\_binding}}{\text{suppressed\_total}}
$$

上述比例在分母为 0 时均置为 `0.0`。

### 5) 输出字段对照

- `summary`：样本规模与输入文件信息（含 `total_evaluable_samples`、`gt_incorrect_count`）。
- `assumptions`：当前口径文字说明（严格 GT 与预测正类定义）。
- `confusion`：`tp/fp/fn/tn`。
- `metrics`：`precision/recall/f1/accuracy`。
- `code_check_stats`：inconclusive 与抑制相关统计。

## 三、新增脚本与职责

### 数据准备

1. `scripts/prepare_error_expansion_samples.py`
- 从 `combined_language_only.json` 流式抽取错题样本。
- 输出 `evaluation` 格式（默认 `data/evaluation_sample_1000_expansion.json`）。
- 支持固定随机种子，保证可复现实验。
- 已修复大对象边界时可能出现的流式解析卡顿风险，新增：
	- `--chunk-size`：控制每次读取块大小（默认 1MB，可调大提速）
	- `--progress-every`：按样本数输出进度日志（stderr）

2. `scripts/prepare_rubric_eval_subset.py`
- 从 `physics_rubric_data_1000.json` 采样 100 条评测样本。
- 生成：
	- `data/evaluation_rubric_100.json`（给 verifier 跑）
	- `data/rubric_eval_100_meta.json`（严格口径对齐元数据）

3. `scripts/prepare_scale_checkpoints.py`
- 对 1000 扩充源按 200 间隔自动切分检查点数据。
- 输出：
	- `data/checkpoints/evaluation_sample_200.json` ... `evaluation_sample_1000.json`
	- `results/scale_curve/checkpoint_manifest.json`

### 指标与曲线

4. `scripts/compute_strict_eval_metrics.py`
- 输入：`run_verifier.py` 的主输出 + symbolic audit + rubric meta。
- 输出严格口径指标 JSON（含 confusion matrix + PRF1 + inconclusive 指标）。

5. `scripts/aggregate_scale_curve.py`
- 聚合多个检查点的 `strict_metrics.json`。
- 输出曲线数据：
	- `results/scale_curve/curve_metrics.csv`
	- `results/scale_curve/curve_metrics.json`

6. `scripts/plot_scale_curve.py`
- 将 `curve_metrics.csv` 渲染为折线图（`results/scale_curve/scale_curve.png`）。

### 流程编排

6. `scripts/generate_scale_runbook.py`
- 基于 `checkpoint_manifest.json` 自动生成：
	- `docs/SCALE_EXPERIMENT_RUNBOOK.md`
	- `scripts/run_scale_checkpoints.sh`
- 只生成命令清单，不自动执行测评。

## 四、建议执行顺序（不直接跑测评）

以下命令用于**准备流程产物与脚本清单**，不会触发完整评测：

```bash
# 1) 构建1000错题扩充源
./.venv/bin/python scripts/prepare_error_expansion_samples.py \
	--input data/combined_language_only.json \
	--output data/evaluation_sample_1000_expansion.json \
	--target-size 1000 \
	--seed 20260331 \
	--chunk-size 8388608 \
	--progress-every 200000

# 2) 构建100条rubric小测评集与严格口径meta
./.venv/bin/python scripts/prepare_rubric_eval_subset.py \
	--input data/physics_rubric_data_1000.json \
	--output-eval data/evaluation_rubric_100.json \
	--output-meta data/rubric_eval_100_meta.json \
	--size 100 \
	--seed 20260331

# 3) 生成每200一道的检查点数据与manifest
./.venv/bin/python scripts/prepare_scale_checkpoints.py \
	--input data/evaluation_sample_1000_expansion.json \
	--output-dir data/checkpoints \
	--step 200 \
	--max-size 1000 \
	--manifest results/scale_curve/checkpoint_manifest.json

# 4) 生成后续完整实验的命令清单（仅生成，不执行）
./.venv/bin/python scripts/generate_scale_runbook.py \
	--manifest results/scale_curve/checkpoint_manifest.json \
	--output-md docs/SCALE_EXPERIMENT_RUNBOOK.md \
	--output-sh scripts/run_scale_checkpoints.sh \
	--model qwen3-30b-a3b

# 5) （检查点评测完成后）聚合曲线数据并绘图
./.venv/bin/python scripts/aggregate_scale_curve.py \
	--metrics-glob 'results/scale_curve/ckpt_*/strict_metrics.json' \
	--output-csv results/scale_curve/curve_metrics.csv \
	--output-json results/scale_curve/curve_metrics.json

./.venv/bin/python scripts/plot_scale_curve.py \
	--input-csv results/scale_curve/curve_metrics.csv \
	--output results/scale_curve/scale_curve.png
```

## 五、后续完整实验（手动按runbook执行）

每个检查点会执行以下链路：

1. `generate_experience_rules.py` 生成经验规则 + 蒸馏结果
2. `generate_symbolic_checks.py` 生成经验代码检查
3. `manage_rule_library.py build` 生成统一规则库
4. `run_verifier.py` 在 `evaluation_rubric_100.json` 上跑小规模评测
5. `compute_strict_eval_metrics.py` 计算严格指标

最后通过 `aggregate_scale_curve.py` 聚合所有检查点指标形成曲线数据。
然后通过 `plot_scale_curve.py` 输出可视化曲线图。
