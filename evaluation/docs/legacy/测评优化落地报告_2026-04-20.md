# 测评优化落地报告（2026-04-20）

## 1. 背景与目标
依据 docs/测评优化说明.md 的要求，本轮优化目标是：
1. 将错误级与题目级测评拆分为两套独立流程（数据、运行、评测、产物互不依赖）。
2. GT 生成从“少量规则化条目”升级为“尽可能完整标注错误”。
3. 位置标注从仅字符级扩展到“段落级可匹配位置”，确保可测评。
4. 两套流程结果都统一输出主指标 recall、precision、f1（辅助指标另列）。

## 2. 当前测评集生成思路（详细）

### 2.1 总体思路：从“条目数量”转向“可定位完整性”
当前 GT 生成不再追求固定条目数（例如每题 3-4 条），而是追求：
1. 尽可能覆盖该错误答案中的主要错误点（exhaustive）。
2. 每条错误必须可回指到作答文本中的局部位置（span 或 paragraph）。
3. 每条错误要可用于评测匹配（locatable_valid 为 true）。

生成流程分为 5 步：
1. 候选错误抽取：强模型从题干、学生作答、参考答案中抽取错误，输出 error + quote + paragraph_index。
2. 结构化归一：统一为 error_item（三元组：error、quote、paragraph_index）。
3. 去重与质量过滤：去重、近重复过滤、伪错误过滤、低置信错误过滤。
4. 位置推断与补全：先做 quote->span，再做 span/quote/declared paragraph 的段落推断。
5. 形成最终 GT：写入 physics_error_gt，并统计 span_valid、paragraph_valid、locatable_valid。

### 2.2 span 的定义与判定
span 表示错误证据在学生作答中的字符区间，采用左闭右开区间 [start_char, end_char)：
1. start_char：0-based 起始字符偏移。
2. end_char：0-based 结束字符偏移（不含）。
3. line_index：由 start_char 映射得到的 1-based 行号。
4. span_valid：满足 start_char >= 0 且 end_char > start_char。

quote 到 span 的定位顺序：
1. exact：大小写敏感精确匹配。
2. case_insensitive：大小写不敏感匹配。
3. whitespace_fuzzy：空白折叠匹配（多空格、换行差异）。
4. normalized_substring：去除 LaTeX 反斜杠、括号/花括号/美元符等噪声后的归一化子串匹配。
5. not_found：以上都失败，span 记为无效。

若同一 quote 命中多个位置，系统记录 span_ambiguous=true，但仍可使用首个命中位置作为可定位依据。

### 2.3 paragraph 的定义、划分与回填
paragraph 表示粗粒度的段落位置，用于在 span 失效时保证可匹配性。

段落划分规则：
1. 不再使用“回答原始空行分段”。
2. 改为按标点 + 长度约束自动切分为细粒度区间（interval bins）。
3. 每个区间目标长度约 220 字符，最小约 120，最大约 360，避免区间过大。
4. paragraph_index 从 1 开始递增（语义上是区间索引）。
5. 每段保留 paragraph_start_char 与 paragraph_end_char（同样按 [start, end)）。
6. 若文本很短，则退化为单一区间。

paragraph 回填优先级：
1. 使用模型声明区间（declared paragraph_index）且有效时直接采用。
2. 若 span_valid=true，则先按 span.start_char 映射区间，再对 span 进行上下文扩展（from_span_context）。
3. 若 span 无效但 quote 可定位，则 quote->span 后做上下文扩展区间（from_quote_context）。
4. 仍失败时，使用 error_text 与各区间文本做 token overlap 选最佳区间（token_overlap）。
5. 仍失败则 paragraph_valid=false。

补充说明：
1. 上下文扩展区间是“偏 span”的窗口（默认左右扩展，且有最大窗口约束），用于替代“整段命中”。
2. 测评时若预测命中该区间（区间重叠或同索引），即可判定该错误被检出。

### 2.4 locatable_valid 的定义
locatable_valid 是“可用于位置评测”的总开关：
1. 当 span_valid=true 或 paragraph_valid=true 时，locatable_valid=true。
2. 评测集质量门、匹配覆盖率、错误级 recall/precision 均以 locatable_valid 为核心口径。

### 2.5 为什么新错误级测评可同时评 recall 与 precision
基于同一份带位置 GT 的错误题集合，已可统一产出两类错误级指标：
1. 错误级 recall：预测覆盖了多少 GT 错误。
2. 错误级 precision：预测出的错误中有多少能在 GT 中找到匹配。

对应定义如下（基于 locatable 错误和 locatable 预测）：
1. 令 G 为 GT 错误集合，P 为预测错误集合。
2. 令 M 为匹配对集合（位置匹配优先，必要时语义辅助）。
3. 错误级 recall = |matched GT| / |G|。
4. 错误级 precision = |matched Pred| / |P|。
5. 错误级 f1 = 2 * precision * recall / (precision + recall)。

主指标命名约定：最终指标统一使用 recall、precision、f1。

## 3.5 span_valid 问题分析与修复（本次新增）

### 问题现象（修复前）
在既有 20 条结果中：
1. span_valid_ratio 约为 0.449（57/127），显著低于 paragraph_valid_ratio=1.0。
2. 典型失败集中在 quote->span not_found。

### 根因定位
1. quote 与原文存在 LaTeX/转义差异：如 \\cdot、\\text{{}}、$...$、括号/空白风格差异，导致 exact/ci/whitespace 仍失败。
2. 原 paragraph 基于空行分段，单段过长，虽可“命中段落”但区间过粗，不利于错误一一对应。
3. 预测侧 location 回填也依赖同样粗段落，放大了“段落可匹配但定位不精确”的问题。

### 修复动作
1. 新增 normalized_substring 回退匹配，针对 LaTeX 形态差异提高 span 命中。
2. paragraph 改为“细粒度自动区间”，不再使用空行分段。
3. span 成功时生成“上下文扩展区间”并写入 paragraph_start/end（偏 span）。
4. 评测侧 paragraph fallback 改为“区间重叠优先 + 同索引兜底”，避免整段过宽误判。

## 6. 测评全流程与计分方式（详细）

### 6.1 全流程分层
当前流程分为两条并行且独立的链路：
1. 错误级链路（Error-Level）：
   - 输入：仅错题、且带 physics_error_gt 标注的数据集。
   - 输出：错误级测评集、检查器输出、错误级指标文件。
2. 题目级链路（Question-Level）：
   - 输入：不带错误 GT、同时含正负例的数据集（仅 expected_has_physics_error 标签）。
   - 输出：题目级测评集、检查器输出、题目级指标文件。

两条链路可以单独运行，互不依赖。

### 6.2 构建层（build_physics_eval_sets.py）
1. 错误级测评集构建：
   - 从错误题候选中抽样/扫描。
   - 强模型生成 error_items（支持 max_errors=0 无上限）。
   - 过滤低质量条目并构造 physics_error_gt（带 span/paragraph）。
   - 按 min_valid_gt_per_sample 门槛筛除不可评样本。
2. 题目级测评集构建：
   - 将 wrong/right 样本转换为无 GT 的题目级样本。
   - 仅保留题目级判定所需字段（id、question、prediction、answer、expected_has_physics_error、eval_split）。

### 6.3 运行层（run_verifier.py + semantic_rule_checker）
1. 对错误级数据集执行检查，得到 error_verifier_results 与 error_symbolic_audit。
2. 对题目级数据集执行检查，得到 question_verifier_results 与 question_symbolic_audit。
3. 两条检查任务在数据和产物层面互不覆盖。

### 6.4 错误级评测层（evaluate_physics_eval_sets.py）
1. GT 侧读取 physics_error_gt，并提取 locatable_valid 错误集合。
2. Pred 侧读取 diagnostics/audit，归一化为 finding；缺失位置则做 span/paragraph 补全。
3. 匹配策略：
   - 一级 span：按 IoU 与 coverage 判定命中。
   - 二级 paragraph/region：span 未命中时，优先按 paragraph_start/end 区间重叠命中；无法比较区间时按 paragraph_index 兜底（可叠加 token 辅助）。
4. 输出主指标：recall、precision、f1。
5. 辅助输出：locatable 覆盖率、IoU、未匹配明细等。

### 6.5 题目级评测层（evaluate_question_level_sets.py）
1. 按 expected_has_physics_error 作为题目级真值标签。
2. 预测端以 diagnostics 与 audit 并集判断 pred_has_error。
3. 构建 TP/FP/TN/FN 后统一输出 recall、precision、f1。
4. 辅助输出可保留 precision_proxy（基于 right 集误报率）。

### 6.6 关键计分口径与公式
错误级主指标（输出字段名固定）：
1. recall = matched_gt_errors / total_gt_errors。
2. precision = matched_pred_locatable / total_pred_locatable。
3. f1 = 2PR / (P+R)。

题目级主指标（输出字段名固定）：
1. recall = TP / (TP + FN)。
2. precision = TP / (TP + FP)。
3. f1 = 2PR / (P+R)。

说明：两套流程均以 recall、precision、f1 作为最终主指标名称；其他诊断指标作为辅助项单独给出。

### 6.7 质量门在全流程中的位置
质量门位于“构建层之后、运行层之前”：
1. 先确保 GT 质量达标，再进入模型测评，避免“劣质 GT 污染指标”。
2. quality_gate_passed=false 时可直接中断错误级流程（require-quality-pass）。

## 8. 新增题目级宽松测评流程（已实现）

在错误级严格评测之外，新增题目级宽松评测，目标是提供更稳定、更易解释的线上看板口径。

### 8.1 题目级宽松评测的定义
1. 题目级 precision（沿用反例思路）：
   - 在“正确题集合”上，只要检出任一错误即记为不准确（FP）。
2. 题目级 recall（新增对称思路）：
   - 在“错误题集合”上，只要检出任一错误即记为命中（TP_hit）。

这一定义不要求逐条错误对齐，只判断“该题是否被系统识别为有错/无错”。

### 8.2 数据与产物
输入数据分组：
1. Wrong Set（错误题集合）：用于题目级 recall。
2. Right Set（正确题集合）：用于题目级 precision。
3. Question Dataset（混合集）：统一以 expected_has_physics_error 进行题目级计分。

输出文件：
1. results/.../question_eval_dataset_{n}_{m}.json
2. results/.../question_top_down_results.json
3. results/.../question_symbolic_audit.json
4. results/.../question_metrics.json

每题最小字段：
1. id
2. split（wrong/right）
3. pred_has_error（是否检出任一错误）
4. diag_count
5. decision_source（diagnostics / audit / merged）

### 8.3 题目级计分方式
令：
1. N_wrong 为错误题总数。
2. N_right 为正确题总数。
3. TP_q 为错误题中 pred_has_error=true 的数量。
4. FP_q 为正确题中 pred_has_error=true 的数量。
5. FN_q = N_wrong - TP_q。

则：
1. recall = TP_q / N_wrong。
2. precision = TP_q / (TP_q + FP_q)。
3. f1 = 2 * precision * recall / (precision + recall)。
4. precision_proxy = 1 - FP_q / N_right（辅助指标）。

### 8.4 题目级宽松流程接入点（已落地）
1. scripts/run_physics_eval_pipeline.py：
   - 默认构建 error_eval_dataset 与 question_eval_dataset。
   - 默认分别执行错误级与题目级检查和评测。
2. scripts/evaluate_question_level_sets.py：
   - 独立输出题目级 recall、precision、f1。
3. pred_has_error 判定统一使用 diagnostics 与 audit 并集（即 finding 是否非空）。

当前状态：流程已实现；本轮已完成 5 条小规模验证，未触发 10/20 条重跑。
