# 规则库背景信息接入方案

更新时间：2026-07-18

## 已确定方向

- 不推翻现有规则库，也不在 verifier 外增加旁路。
- 规则库改为较粗的层级，细化判断放到 API 语义树导航中。
- 正式检索路径为 `Domain → Topic → ScenarioCluster → Rule`。
- 词法检索只用于离线诊断，不是正式结果，也不允许自动回退。

## 各层输入

```text
question + context
  → BackgroundAnalysis（当前小问、对象、过程、条件、待求量、缺失信息、非当前背景）
  → Domain
  → Topic
  → ScenarioCluster

question + context + BackgroundAnalysis + prediction（分字段提供）
  → Rule
  → Semantic Checker
```

- `question + context` 是题目背景，决定物理系统、过程和规则适用条件。
- BackgroundAnalysis 与 Domain 在同一次 API 调用中生成，不是 verifier 外的旁路。
- `prediction` 是待检查答案，只能用于定位解题步骤和错误，不得补造题设条件。
- 参考答案不进入 verifier。

## 每题必须保存的结果

- 选中的 Domain、Topic、ScenarioCluster、Rule。
- 各层语义分数和简短理由。
- API 失败的具体层级。
- 每层实际候选 ID/名称、Rule 批次、模型原始响应、接受项和拒绝原因。
- 模型未返回的候选单列为 `not_returned_by_model`，不伪造拒绝理由。
- 最终诊断、quote 定位和发布门结果。
- 词法匹配分数仅作为审计字段，与语义分数分开。

## 实施顺序

1. 把现有 API 语义树接回最新版 verifier。
2. 固定各层输入边界，补离线测试，禁止隐式词法回退。
3. 用典型样本跑出逐层结果，与学长核对检索路径。
4. 在服务器跑全流程，对比规则召回、最终召回率和 FP。
5. 根据真实失败路径设计规则库粗放化和动态扩展方案。

当前已完成稳定 Domain/Topic ID、结构化背景、候选 hints、响应合约重试、Domain/Topic/ScenarioCluster 空结果二次确认、层内断点结果和可解释 trace。ScenarioCluster 是硬边界：已有 Cluster 时不再扫描整个 Topic 的数百条规则；通用推理规则只在具体路径无命中时兜底。六题离线测试使用真实题面和完整目录，仅验证候选连通性，不作为召回率或 FP 指标。下一步在服务器重跑真实 API；规则库结构调整必须由真实结果驱动。

## 典型样本运行

所有调用 API 的检索、训练和测评统一在服务器运行。本机只做无 API 的开发与离线测试。

当前服务器环境：

- 主机：`visitor@node13`
- 仓库：`~/huhengyuan/PhysicsVerifier`
- conda 环境：`physics`
- 长时间 API 任务：默认使用 `tmux`，并保存运行日志

确认 API 环境变量已经配置后，新建会话并运行：

```bash
tmux new -s semantic-retrieval
cd ~/huhengyuan/PhysicsVerifier
conda activate physics
export OPENAI_DISABLE_THINKING=1
mkdir -p results/background_retrieval
set -o pipefail
python scripts/run_verifier.py \
  --retrieval-only \
  --unified-retrieval-mode semantic \
  --input data/typical_samples.json \
  --output results/background_retrieval/semantic_tree_results_v2.json \
  --unified-catalog catalogs/rules_unified_3000_runtime_backfilled.json \
  --model qwen3-30b-a3b \
  --unified-rule-top-n 6 \
  --semantic-json-attempts 4 \
  --continue-on-semantic-error \
  --progress-interval 1 \
  --verbose-per-sample \
  2>&1 | tee results/background_retrieval/semantic_tree_v2_run.log
```

按 `Ctrl+B`、再按 `D` 可退出会话而不中止任务；使用 `tmux attach -t semantic-retrieval` 恢复，使用 `tmux ls` 查看会话。

该命令只运行检索，不调用后续 Checker。每完成一题就原子更新结果文件，中断后仍保留已完成样本。成功标准是日志中的 `rule_hit_samples` 大于 0，且结果文件能看到具体 `retrieved_rules`；整批无规则命中时程序退出码为 3，API/合约错误退出码为 2。
