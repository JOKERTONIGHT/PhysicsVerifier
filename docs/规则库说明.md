# 规则库说明

## 当前结构

统一规则库的运行结构为：

```text
Domain → Topic → Scenario Cluster → Rule Group → Rule
```

`Rule Group` 是可选内部层。运行时以 Scenario Cluster 为检索边界，不在命中具体 Cluster 后重新扫描整个 Topic。

## 当前规模

- 6 个 Domain。
- 123 个 Topic，其中 93 个包含可执行规则。
- 488 个 Scenario Cluster。
- 4875 条可执行规则。
- 1082 条自顶向下知识规则作为知识参考。

## 主要文件

| 文件 | 作用 |
|---|---|
| `catalogs/rules_catalog_top_down.json` | 物理知识骨架 |
| `catalogs/rules_300_tagged.json` | 300 样本标注规则输入 |
| `catalogs/semantic_experience_distilled_300.json` | 300 样本蒸馏规则输入 |
| `catalogs/scenario_cluster_blueprints.json` | Scenario Cluster 的正式配置源 |
| `catalogs/rules_unified.json` | 514 条规则基线库 |
| `catalogs/rules_unified_3000.json` | 扩展后的统一规则候选库 |
| `catalogs/rules_unified_3000_runtime_backfilled.json` | verifier 当前运行库 |
| `catalogs/legacy/` | 历史版本，不用于当前主流程 |
| `scripts/build_unified_catalog.py` | 统一规则库构建脚本 |
| `scripts/unified_rules_pipeline.py` | 规则库构建主入口 |
| `scripts/validate_unified_catalog_structure.py` | 最终目录结构验证 |

运行库是构建产物，不直接手工修改。新增和修正规则应进入构建输入，再通过统一流水线重建和验证。

## 新版构建流程

```text
样本抽取候选
→ 候选聚类
→ 多样本候选概括为正式规则
→ 正式规则重新聚类
→ 生成规则树
→ 全量结构验证
```

关键约束：

- 单样本经验只能作为候选，不能直接进入正式规则库。
- 候选、残余项和失败批次必须全部保留，不能静默丢失。
- 候选聚类和正式规则聚类使用不同文件与缓存。
- 新增 Topic 即使没有人工蓝图，也会生成通用回退簇，保证规则可检索。
- 正式构建只接受完整的全量概括结果。
- 最终验证要求 Rule ID 唯一、引用合法、每条规则在树中恰好可达一次。
- API 概括默认关闭 thinking，单次请求默认 120 秒超时；失败批次可记录并续跑，不允许无限等待。
- 候选概括使用 DeepSeek V4 Flash 非思考模型，接口异常时切换 Gemini 备用模型。
- 服务器全量实验前，必须先在本地 conda 环境完成真实小样本运行和结构校验。

题目背景只参与运行时的语义导航，不写入正式规则的核心逻辑。
