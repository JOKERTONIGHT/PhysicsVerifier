# 项目进展

- 现有统一规则库可用于 verifier，不推翻重建。
- API 语义树已接入主流程：`BackgroundAnalysis + Domain → Topic → Scenario Cluster → Rule`。
- Domain、Topic、Cluster 只读取题目背景；Rule 才读取待检查答案。
- 新版规则构建完成：4361 条候选概括为 609 条多样本规则，与 514 条基线规则组成 1123 条正式规则。
- 新版目录包含 189 个 Scenario Cluster，全部规则可达且没有重复分配。
- 叶节点粗化验收通过：候选、正式规则和目录规则数量守恒，残余桶最大 12 条，无大兜底簇。
- 导航修复后六条样本结构错误为 0；四条发布规则，两条正常为空。
- 增量更新流程已建立：隔离工作区、缓存复用、全目录验证和人工发布审核。
- 8 条独立新错解已完成增量实测：抽取 9 条新候选，形成 16 条新增正式规则。
- 增量目录保留原有 1123 条 Rule ID，删除 0 条；最终 1139 条规则全部唯一且可达。
- 新目录检索 8/8 跑完且结构错误为 0；完整 verifier 回归 2/2 跑完并成功进入 Semantic Checker。
- 当前质量门禁评分为 97，状态为 `usable_with_known_gaps`；缺口是部分样本没有合适规则，不是流程接入失败。

## 当前规则库形式

- 单题抽取结果只作为带来源候选，不直接作为 verifier 正式规则。
- 候选在 Topic 内聚类，并由多样本共同支持后概括为正式规则。
- 正式规则按 `Domain → Topic → Scenario Cluster → Rule` 组织。
- 题目背景负责树内导航，到 Rule 层才结合待检查答案。
- 新样本通过候选池局部增量更新；旧 Rule ID 保留，删除会阻断接入。

## 当前判断

API 输出和粗化规则树已经稳定。确认失败后会进行一次有界树内恢复，不会因错误的临时候选提前停止。

- `154795`：找到“磁通量积分变量校验”，但题目背景缺少完整几何信息，最终拒绝。
- `62392`：命中两条静电压力规则。
- `142854`：命中“理想电表接入审计”。
- `194394`：没有误用径向固有距离规则；当前库缺少角向周长机制。

剩余两条分别属于背景缺失和规则机制缺失，不再是导航结构故障。

## 下一步

1. 固定当前规则构建、增量更新和背景语义导航结构。
2. 准备独立测评集，明确召回、FP 和空检索的统计口径。
3. 对失败样本按背景、Topic、Cluster、Rule 和 Checker 分阶段归因。
4. 根据总体测评结果决定后续改动，不再围绕少量增量样本调参。
5. 与学长同步测评输入、输出和检索 trace 接口。

## 当前边界

- 不继续批量调用 API 补 metadata。
- 不生成新的平行规则库。
- 不把参考答案提供给 verifier。
- 不在缺少对照实验时宣称召回率或 FP 已改善。
- 本次新样本仅 1/8 返回规则，说明流程已跑通，但不能据此认为检索效果已经改善。
- 不用六个典型样本反复调整固定规则命中。
- 不把当前工作目标扩展为构造一个逐题精确命中的完整检查器。
