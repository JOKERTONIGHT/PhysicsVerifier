# 项目进展

## 当前状态

- 现有统一规则库可用于 verifier，不推翻重建。
- API 语义树已接入主流程：`BackgroundAnalysis + Domain → Topic → Scenario Cluster → Rule`。
- Domain、Topic、Cluster 只读取题目背景；Rule 才读取待检查答案。
- 语义输出使用强制工具调用和严格合约，格式错误会重试并记录失败层级。
- 检索结果保留逐层候选、响应摘要、接受项、拒绝项和部分完成结果。
- 本地真实 API 冒烟运行已能完整输出规则；这只证明流程可运行，不代表规则选择最优。

## 当前判断

规则库叶子存在过细和相近规则重复的问题。典型样本只用于观察路径，不再要求命中固定 `rule_id`，也不作为召回率或 FP 证据。

## 下一步

1. 用更大且独立的样本集跑全流程，统计规则召回、最终召回率和 FP。
2. 根据真实失败分布设计规则叶子合并，减少过细分支。
3. 设计规则库增量更新机制，使新规则可以持续加入而不必整库重建。

## 当前边界

- 不继续批量调用 API 补 metadata。
- 不生成新的平行规则库。
- 不把参考答案提供给 verifier。
- 不在缺少对照实验时宣称召回率或 FP 已改善。
- 不用六个典型样本反复调整固定规则命中。
