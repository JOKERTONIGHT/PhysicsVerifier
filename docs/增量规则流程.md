# 增量规则流程

## 目标

新增样本只补充现有规则库，不生成平行规则库，也不直接把单题规则写成正式规则。

## 流程

```text
新增样本
→ 抽取带来源的候选规则
→ 并入候选池
→ 仅为新增或变化候选计算 embedding
→ 在受影响 Topic 内重新聚类、概括
→ 将概括结果与现有正式规则比较
→ 更新受影响 Topic 的正式规则和规则簇
→ 重建完整目录并做结构、检索回归
```

处理原则：

- 与正式规则完全相同：不新增规则，只记录已覆盖。
- 与候选完全相同：合并 `sample_ids` 和支持数量。
- 语义相近：交给 Topic 内 embedding 聚类，不用字符串规则自动合并。
- 只有一个样本支持：继续留在候选池。
- 至少两个不同样本支持同一机制：允许概括为正式规则。
- 概括结果与已有正式规则同机制：保留原 Rule ID，只补来源和支持。
- 概括结果是新机制：新增正式规则；不确定项进入人工审核，不自动覆盖。
- 当前正式目录是增量构建的权威基线；增量过程不得自动删除旧 Rule ID。
- 未受影响 Topic 保持不变；Rule ID 和来源关系必须保留。

## 准备入口

```bash
python scripts/prepare_incremental_update.py \
  --new-candidates results/unified_rules_incremental/new_candidates.json
```

该命令不调用 API，也不修改当前正式库。它会：

- 合并候选并输出受影响 Topic。
- 建立 `results/unified_rules_incremental/` 隔离工作区。
- 复用当前概括和簇命名结果作为续跑起点。
- 在 `incremental_manifest.json` 中生成六步运行清单。

按清单依次运行后，`finalize_incremental_update.py` 会生成候选目录和审核报告。embedding 缓存只补充新增内容；未变化的概括批次和 Topic 簇命名直接复用。

最终产物不会自动覆盖 `catalogs/rules_unified_3000.json`。只有结构验证、变化范围审核和独立检索回归全部通过后，才人工替换正式目录。

验证阶段可直接接入主流程：

```bash
python scripts/run_verifier.py \
  --input data/test.json \
  --output results/test.json \
  --unified-catalog results/unified_rules_incremental/rules_unified_incremental.json \
  --unified-retrieval-mode semantic
```

## 验收

- 新候选、重复候选、正式规则已覆盖项数量守恒。
- 未受影响 Topic 的规则与规则簇不变化。
- 最终目录无重复 Rule ID、无失联规则、无非法引用。
- 新增 Rule ID 必须进入 `incremental_validation.json` 人工审核；任何旧 Rule ID 被删除都会阻断接入。
- 本地独立样本检索无结构错误后，才上服务器跑较大实验。
